## TS behavior to preserve

Normative application behavior is pinned to TS `2bc799a8d8e535242e6de2d305f426ce3975ea7b`; [`infra/overlay-server/src/index.ts:372–373`](https://github.com/bsv-blockchain/ts-stack/blob/2bc799a8d8e535242e6de2d305f426ce3975ea7b/infra/overlay-server/src/index.ts#L372) registers the real topic and lookup service.

- [`IdentityTopicManager`](https://github.com/bsv-blockchain/ts-stack/blob/2bc799a8d8e535242e6de2d305f426ce3975ea7b/packages/overlays/topics/src/identity/IdentityTopicManager.ts#L11) parses BEEF/output PushDrop fields, verifies the subject's signature using protocol `[1, 'identity']` and key ID `'1'`, verifies the certificate, and requires publicly decryptable attributes. It admits valid output indices independently and returns empty `coinsToRetain`. Engine-level transaction/SPV validation remains a separate mandatory requirement.
- [`IdentityLookupService`](https://github.com/bsv-blockchain/ts-stack/blob/2bc799a8d8e535242e6de2d305f426ce3975ea7b/packages/overlays/topics/src/identity/IdentityLookupService.ts#L14) indexes admitted `tm_identity` outputs, decrypts public certificate fields, and removes records on spend/eviction. Its query precedence is serial number, attributes, identity key plus certificate types, identity key, then certifiers; it forwards limit/offset and returns outpoint formulas.
- [`IdentityStorageManager`](https://github.com/bsv-blockchain/ts-stack/blob/2bc799a8d8e535242e6de2d305f426ce3975ea7b/packages/overlays/topics/src/identity/IdentityStorageManager.ts#L13) uses unique outpoint upserts, certificate/search indexes, and searchable attributes excluding `profilePhoto`/`icon`. Preserve its characterized attribute/text/username matching and pagination semantics. Approved bounds, durability and continuation corrections belong to the existing W00/W02/storage contracts; do not infer a new global ordering guarantee from this implementation.

## Smallest ownership proposal

Assign a service-specific companion package, proposed `go-overlay-services/pkg/topics/identity`, to the maintained Go engine/server lane. This directory is a proposal, not existing code. Implement the two injected interfaces and identity query/projection types there; keep identity rules outside generic engine logic and SDK/wallet client glue. Existing Go SDK PushDrop and verifiable-certificate primitives are candidates for reuse, subject to cross-language certificate/signature/decryption fixtures.

Inject the identity projection through the S01/S04 Mongo capability work, with replay-safe writes/deletes and the existing S05 index/rebuild contract. Wire `tm_identity` and `ls_identity` through [`engine.Config`](https://github.com/bsv-blockchain/go-overlay-services/blob/f5d8074be085c1970e113bc8ee55fecbab251fcf/pkg/core/engine/engine.go#L117), return formulas for the engine's [BEEF hydration](https://github.com/bsv-blockchain/go-overlay-services/blob/f5d8074be085c1970e113bc8ee55fecbab251fcf/pkg/core/engine/engine.go#L723), and mount the real engine with [`server.WithEngine`](https://github.com/bsv-blockchain/go-overlay-services/blob/f5d8074be085c1970e113bc8ee55fecbab251fcf/pkg/server/server_http.go#L104) in the S07 host/profile. The default no-op engine is insufficient. This requires no new repository or port of unrelated TS topics.

Acceptance must exercise actual Go admission, persistent projection and HTTP lookup from the real TS IdentityClient/wallet path: valid certificate BEEF, malformed/signature/proof rejection, query compatibility, replay, spend/eviction and restart behavior. Deterministic fixtures may drive that real server; hard-coded fixture responses do not establish server parity. BASM/GASP identity-history integration still needs its own gates. This is a necessary implementation dependency of the already-approved primary profile, not a scope change or a deployment assumption. No implementation, integration test, source edit, dependency change or deployment was performed here; originating root owns assignment and acceptance.
